# Browser Interface

HAVI uses minimal browser chrome and internal admin pages.

## Toolbar

Toolbar actions:

- back/forward navigation
- address input
- URL share
- folder import
- edit current page
- admin panel toggle
- new tab

Address input accepts:

- full HPPR URLs
- `//group/app/path` coordinates
- `group/app/path` shorthand

Non-URL coordinate input is normalized to `hppr://`.

## Home page

New tabs open `havi:///overview`.

Overview provides:

- URL entry
- shortcuts to key namespaces and routes
- links to admin pages

## Admin pages

Core internal pages:

- `havi:///overview`
- `havi:///home-repo`
- `havi:///routes`
- `havi:///ring0`

### Ring0 proxy queue

`havi:///ring0` handles privileged operation approvals requested by site Ring1
identities.

Behavior:

1. watch request paths
2. show requester, command, and target
3. approve: execute with ring0 and write reply
4. deny: write forbidden reply

This provides controlled escalation with explicit user approval.

## Directory listing UI

URLs ending with `/` render LIST results as clickable directory pages.

## Credentials

Local admin credentials are stored at:

`~/.config/HAVI/credentials/<home-repo-key>`

Format:

1. ring1 name
2. token

Startup flow:

1. HELLO to get home repo key
2. load credentials for that key
3. if missing, bootstrap with `ring0/init`

Site credentials for route operations are cached in memory per group/app.

## Configuration

Environment variables:

- `HAVI_HOME` (default `~/.config/HAVI`)
- `HAVI_REPO`

`HAVI_REPO` supports:

- `tcp+<host>[:<port>]`
- `unix+<path>`
- `path:<dir>`

When unset, HAVI runs an embedded repo at `$HAVI_HOME/repo`.
